# Integrating DALL·E 2 API with TruLens: Elevating Image Generation Capabilities

In this tutorial I will show you how to combine two powerful tools: the [DALL·E 2 API](https://platform.openai.com/docs/guides/images/usage?context=node) for generating images from text prompts, and [TruLens](https://lablab.ai/tech/truera/trulens) for evaluating and improving the quality of your AI application. We will build a small Streamlit app that generates an image with [DALL·E 2](https://lablab.ai/tech/openai/dall-e-2), captions the generated image with a vision-language model, and records the prompt-to-caption quality inside TruLens.

The goal is not just to generate a pretty image. The goal is to create a feedback loop: generate, evaluate, refine, and generate again. That loop is exactly what makes an AI prototype feel like a real product.

## Why DALL·E 2 and TruLens Work Well Together

DALL·E 2 is an image generation model from OpenAI. You give it a text prompt, and it returns one or more images that match the prompt. The API is simple, but building a reliable application around it is not always simple. Prompts can be ambiguous, outputs can drift from the original intent, and it is hard to know whether a prompt change actually improved the result.

TruLens helps with that second problem. TruLens Evals gives you instrumentation and feedback functions for LLM-based applications. You can wrap your application, record inputs and outputs, and attach feedback functions that score quality. For a DALL·E 2 app, we can use TruLens to evaluate the relationship between the original prompt and a caption of the generated image. If the caption does not match the prompt, that is a strong signal that the image may not match the prompt either.

This is a practical pattern for hackathons because it gives you a measurable improvement loop without requiring a full research pipeline.

## Understanding the DALL·E 2 API

The DALL·E 2 API is part of the OpenAI Images API. In modern OpenAI Python SDK versions, you call it through the `images.generate` method. A minimal request looks like this:

```python
from openai import OpenAI

client = OpenAI()

response = client.images.generate(
    model="dall-e-2",
    prompt="A cozy reading nook with warm sunlight and plants",
    size="1024x1024",
    n=1,
)

image_url = response.data[0].url
print(image_url)
```

The response contains a URL to the generated image. DALL·E 2 supports several image sizes, including `256x256`, `512x512`, and `1024x1024`. For most demos, `1024x1024` is a good default because it gives enough detail for a portfolio or hackathon presentation.

### Important DALL·E 2 API Details

- Use `model="dall-e-2"` explicitly so your app does not accidentally switch to another image model.
- Keep prompts descriptive but focused. DALL·E 2 responds well to subject, style, lighting, composition, and mood.
- Generated image URLs are temporary. If you need to keep an image, download it and store it yourself.
- The API returns image URLs by default. You can also request base64 data with `response_format="b64_json"` if your app needs to avoid external URLs.

### A Better Prompt Template

A useful prompt template for DALL·E 2 is:

```text
[subject] + [environment] + [lighting] + [style] + [composition] + [quality details]
```

For example:

```text
A friendly robot barista in a small futuristic coffee shop, warm morning light,
cinematic composition, soft shadows, highly detailed digital illustration
```

This structure gives the model enough constraints to produce a coherent image while still leaving room for creativity.

## Understanding TruLens Evals

TruLens Evals is designed for evaluating LLM applications. It records inputs, outputs, and metadata, then applies feedback functions to score quality. Common feedback functions include groundedness, relevance, language match, and toxicity. You can also write custom feedback functions.

For image generation, we cannot directly score pixels with TruLens out of the box. Instead, we use a bridge: we caption the generated image with a vision-language model, then evaluate the caption against the original prompt. This gives us a text-based proxy for prompt adherence.

The workflow looks like this:

1. User enters a prompt.
2. DALL·E 2 generates an image.
3. A vision-language model captions the image.
4. TruLens records the prompt and caption.
5. TruLens feedback functions score the prompt-caption relationship.
6. The developer inspects the scores and refines the prompt if needed.

This is not a perfect replacement for human evaluation, but it is a fast and useful signal during development.

### Step 5: Write the Complete Streamlit Application

Create `app.py` and paste the following complete code:

```python
import json
import os

import requests
import streamlit as st
from dotenv import load_dotenv
from openai import OpenAI
from trulens_eval import Feedback, Huggingface, Tru, TruBasicApp

load_dotenv()

st.set_page_config(
    page_title="DALL·E 2 + TruLens",
    page_icon="🎨",
    layout="wide",
)

OPENAI_API_KEY = st.secrets.get("OPENAI_API_KEY", os.getenv("OPENAI_API_KEY"))
HUGGINGFACE_API_KEY = st.secrets.get(
    "HUGGINGFACE_API_KEY", os.getenv("HUGGINGFACE_API_KEY")
)

if not OPENAI_API_KEY:
    st.error(
        "Missing OPENAI_API_KEY. Add it to .streamlit/secrets.toml or your environment."
    )
    st.stop()

if not HUGGINGFACE_API_KEY:
    st.error(
        "Missing HUGGINGFACE_API_KEY. Add it to .streamlit/secrets.toml or your environment."
    )
    st.stop()

client = OpenAI(api_key=OPENAI_API_KEY)

HF_CAPTION_MODEL_URL = (
    "https://api-inference.huggingface.co/models/"
    "Salesforce/blip-image-captioning-large"
)


def generate_dalle_image(prompt: str, size: str = "1024x1024") -> str:
    """Generate an image with DALL·E 2 and return its temporary URL."""
    response = client.images.generate(
        model="dall-e-2",
        prompt=prompt,
        size=size,
        n=1,
    )
    return response.data[0].url


def caption_image_bytes(image_bytes: bytes) -> str:
    """Caption an image with a Hugging Face image-to-text model."""
    headers = {"Authorization": f"Bearer {HUGGINGFACE_API_KEY}"}
    response = requests.post(
        HF_CAPTION_MODEL_URL,
        headers=headers,
        data=image_bytes,
        timeout=120,
    )
    response.raise_for_status()
    payload = response.json()

    if isinstance(payload, list) and payload:
        return payload[0].get("generated_text", "")

    if isinstance(payload, dict):
        return payload.get("generated_text", str(payload))

    return str(payload)


def generate_and_caption(prompt: str) -> str:
    """
    Generate a DALL·E 2 image, caption it, and return a JSON string.

    Returning JSON keeps both the image URL and the caption together while
    still giving TruLens a text output to record and evaluate.
    """
    image_url = generate_dalle_image(prompt)
    image_response = requests.get(image_url, timeout=120)
    image_response.raise_for_status()
    caption = caption_image_bytes(image_response.content)

    return json.dumps(
        {
            "image_url": image_url,
            "caption": caption,
        }
    )


def prompt_caption_relevance(input_prompt: str, output_json: str) -> float:
    """
    A simple custom feedback function.

    It measures how many words from the prompt appear in the generated image
    caption. This is intentionally lightweight and easy to understand. For a
    production app, you could replace it with an LLM-based relevance judge.
    """
    try:
        data = json.loads(output_json)
        caption = data.get("caption", "")
    except json.JSONDecodeError:
        caption = output_json

    prompt_words = {
        word.strip(".,!?;:()[]{}'\"").lower()
        for word in input_prompt.split()
        if word.strip(".,!?;:()[]{}'\"")
    }
    caption_words = {
        word.strip(".,!?;:()[]{}'\"").lower()
        for word in caption.split()
        if word.strip(".,!?;:()[]{}'\"")
    }

    if not prompt_words:
        return 0.0

    overlap = len(prompt_words.intersection(caption_words)) / len(prompt_words)
    return float(overlap)


huggingface_client = Huggingface(api_key=HUGGINGFACE_API_KEY)

f_lang_match = Feedback(huggingface_client.language_match).on_input_output()

f_prompt_caption_relevance = Feedback(
    prompt_caption_relevance,
    name="Prompt-Caption Relevance",
).on_input_output()

tru_app = TruBasicApp(
    generate_and_caption,
    app_id="dalle2_trulens_demo",
    feedbacks=[f_lang_match, f_prompt_caption_relevance],
)


def run_tru_app(prompt: str) -> str:
    """Run the wrapped app inside a TruLens recording context."""
    with tru_app as recording:
        result_json = tru_app.app(prompt)
    return result_json


st.title("DALL·E 2 + TruLens")
st.caption(
    "Generate an image, caption it, and evaluate prompt adherence with TruLens."
)

with st.sidebar:
    st.header("Settings")
    image_size = st.selectbox(
        "Image size",
        options=["1024x1024", "512x512", "256x256"],
        index=0,
    )
    st.markdown("---")
    st.markdown(
        "Run the TruLens dashboard in a separate terminal:\n\n"
        "```bash\n"
        "python -c \"from trulens_eval import Tru; Tru().run_dashboard()\"\n"
        "```"
    )

prompt = st.text_area(
    "Describe the image you want to generate",
    value=(
        "A friendly robot barista in a small futuristic coffee shop, "
        "warm morning light, cinematic composition, highly detailed illustration"
    ),
    height=120,
)

col1, col2 = st.columns([1, 1])

with col1:
    generate_clicked = st.button("Generate and evaluate", type="primary")

with col2:
    st.write("")

if generate_clicked:
    if not prompt.strip():
        st.warning("Please enter a prompt first.")
    else:
        with st.spinner("Generating image with DALL·E 2..."):
            try:
                result_json = run_tru_app(prompt)
                result = json.loads(result_json)

                st.subheader("Generated Image")
                st.image(
                    result["image_url"],
                    caption=result["caption"],
                    use_column_width=True,
                )

                st.subheader("Image Caption")
                st.write(result["caption"])

                st.subheader("TruLens Recording")
                st.success(
                    "This run was recorded in TruLens. Open the dashboard to "
                    "inspect feedback scores and compare prompts."
                )

                st.info(
                    "If the caption does not match your prompt, refine the prompt "
                    "with more concrete subject, style, lighting, and composition "
                    "details, then run it again."
                )

            except Exception as exc:
                st.error(f"Something went wrong: {exc}")
```

## How the Application Works

Let's walk through the important parts of the code.

### `generate_dalle_image(prompt, size)`

This function calls the DALL·E 2 API:

```python
response = client.images.generate(
    model="dall-e-2",
    prompt=prompt,
    size=size,
    n=1,
)
return response.data[0].url
```

It returns the temporary image URL. The rest of the app downloads the image bytes so the captioning model can analyze the actual image.

### `caption_image_bytes(image_bytes)`

This function sends the image bytes to a Hugging Face image-to-text model. The model returns a short caption such as:

```text
a robot standing in a coffee shop
```

That caption becomes the text representation of the generated image.

### `generate_and_caption(prompt)`

This is the function wrapped by TruLens. It performs the full pipeline:

1. Generate the image with DALL·E 2.
2. Download the image.
3. Caption the image.
4. Return a JSON string containing both the image URL and the caption.

Returning JSON is a practical choice because TruLens records text outputs. We keep the image URL for the Streamlit UI and the caption for evaluation.

### `prompt_caption_relevance(input_prompt, output_json)`

This custom feedback function compares the original prompt with the generated caption. It is intentionally simple: it measures word overlap. That makes it easy to understand and fast to run.

In a production system, you could replace this with an LLM-based judge that asks:

```text
Does this caption accurately describe an image that would satisfy the original prompt?
```

For a hackathon, the simple version is often enough to demonstrate the evaluation loop.

### `TruBasicApp`

`TruBasicApp` wraps our pipeline and records each run. The `feedbacks` argument attaches the language-match feedback and our custom prompt-caption relevance feedback. When we call `run_tru_app(prompt)`, TruLens records the input, output, and feedback scores.

## Using TruLens Evals to Improve DALL·E 2 Output

Now let's look at the practical improvement loop. This is the part I recommend showing in your hackathon demo.

### Step 1: Start with a Vague Prompt

Try a prompt like:

```text
a dog
```

DALL·E 2 will generate an image, but the result may be generic. The caption might be something like:

```text
a dog sitting on the grass
```

The prompt-caption relevance may be high because the word "dog" appears, but the image may not match the style or mood you wanted.

### Step 2: Add Concrete Details

Refine the prompt:

```text
a golden retriever puppy sitting in a sunlit meadow, soft morning light,
shallow depth of field, warm colors, professional pet photography
```

Now the caption is more likely to include details such as "dog", "grass", "sunlight", or "meadow". The relevance score becomes more meaningful because the prompt contains more evaluable concepts.

### Step 3: Compare Runs in TruLens

Run both prompts and open the TruLens dashboard. Compare:

- The original prompt.
- The generated caption.
- The language-match score.
- The prompt-caption relevance score.

If the refined prompt scores higher, you have evidence that the added details improved prompt adherence. If it scores lower, inspect the caption to understand why. Maybe the model focused on the wrong subject, or maybe the captioning model missed an important detail.

### Step 4: Iterate

Use the feedback to adjust the prompt. Good refinements usually add:

- A clear subject.
- A specific environment.
- Lighting details.
- Style or medium.
- Composition or camera angle.
- Quality descriptors.

This loop is simple, but it demonstrates a real evaluation-driven workflow.

## Tips for Hackathon Participants

Here are a few practical tips if you are building with DALL·E 2 and TruLens during a hackathon.

### Keep the Evaluation Loop Small

You do not need a perfect evaluation system. A simple feedback function that compares the prompt with a generated caption is enough to demonstrate the value of TruLens. Focus on showing the loop: generate, evaluate, refine, compare.

### Use Caching During Development

DALL·E 2 calls cost money and take time. During development, cache generated image URLs or save images locally so you do not regenerate the same prompt repeatedly. Streamlit's `st.cache_data` is a quick way to add caching.

### Make the Demo Visual

Show the prompt, the generated image, the caption, and the TruLens feedback score side by side. Judges and viewers understand the value immediately when they can see the before-and-after improvement.

### Be Honest About the Proxy Metric

Caption-based evaluation is a proxy for image quality. It is not a perfect measure of aesthetics or prompt adherence. Explain that clearly in your demo. Then explain how you would improve it with a stronger vision-language judge or human evaluation.

### Add a Prompt Refinement Step

If you have time, add a button that asks an LLM to rewrite the user's prompt with more detail. Then run both the original and refined prompts through the same TruLens evaluation pipeline. This creates a compelling demo of automated prompt optimization.
